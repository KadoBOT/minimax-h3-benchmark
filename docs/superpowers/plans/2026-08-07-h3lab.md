# H3 Lab Implementation Plan

> **For agentic workers:** implement task-by-task, in order. Steps use checkbox syntax.
> Ledger: `../specs/2026-08-07-h3lab-phases.md` is the source of truth for progress.

**Goal:** Replace the MiniMax H3 benchmark with a lab that records runs durably, makes
judging them fast, and answers which configurations work using paired comparisons.

**Architecture:** Pure `h3lab.domain` (no I/O) under a row-level SQLite `storage` layer, a
`comfy` adapter that hides node surgery behind `build_prompt`, an `engine` with a
DB-backed queue and an event bus, a FastAPI `api`, and a React/shadcn frontend in `web/`
served as static files by the same process.

**Tech Stack:** Python 3.14, FastAPI 0.136, pydantic 2.13, uvicorn, sqlite3 (WAL),
websockets, ffmpeg/ffprobe (external, optional). Vite 7, React 19, TypeScript strict,
Tailwind v4, shadcn/ui, TanStack Query, react-router-dom, lucide-react, Vitest.

## Global Constraints

- Domain modules import nothing from `storage`, `comfy`, `engine`, or `api`.
- No whole-table rewrites. Every mutation is a targeted `UPDATE` or `INSERT`.
- Run identity is the opaque `id`. `seq` and `label` are display only.
- Every "X beats Y" claim carries its sample size; fewer than two pair groups is
  `inconclusive`.
- Exactly one primary `score`; weights come from the caller; guardrails stay separate.
- All filesystem paths resolve through `Settings`; no absolute path literals outside its
  defaults.
- Tests use worked-example expected values, never a recomputation of the implementation.
- Tailwind: `gap-*` not `space-y-*`; semantic tokens not raw colours; shadcn `Field` for
  form rows.

### Task 2: Generation config and identity

**Files:** Create `h3lab/domain/config.py`, `tests/test_domain_config.py`

**Produces:**
```python
HASHED_FIELDS: tuple[str, ...]      # sampling-relevant fields, ordered
RECIPE_EXCLUDED: frozenset[str]     # {"seed"}
class GenerationConfig(BaseModel):  # pydantic, model_config = ConfigDict(frozen=True, extra="forbid")
def canonical_form(cfg, *, exclude=()) -> str
```

Validation rules on `GenerationConfig`: `mode` in `{flf2v,t2v,r2v}`; `steps` 1–200;

- [ ] Canonical form is sorted-key JSON with `separators=(",",":")` over `HASHED_FIELDS`

- [ ] Test: two configs differing only in `seed` share a `recipe_hash` and differ in
      `config_hash`; expected hash asserted against a literal captured once and pinned
      (regression pin, documented as such); `extra="forbid"` rejects a typo'd field with a
      422-able `ValidationError`; `flf2v` without `first_frame` raises.

### Task 6: Insights

**Files:** Create `h3lab/domain/insights.py`, `tests/test_domain_insights.py`

**Produces:**
```python
AXES: tuple[AxisDef, ...]                      # field, label, kind
def marginal(runs, axis) -> list[MarginalCell] # value, n, n_rated, mean_stars, median_stars, mean_sec_per_it, mean_wall_s
def paired(runs, axis) -> PairedResult          # comparisons + pair_groups + verdict
def analyse(runs, axis, *, elo=None) -> AxisInsight
```
`paired` keys each run by `recipe_hash` recomputed with `{axis, "seed"}` excluded, keeps
groups holding ≥ 2 distinct axis values, and for each unordered value pair records the
per-group delta in stars (rated only) and in `sec_per_it`. Aggregates give `pair_groups`,
`mean_delta`, `stderr`, `wins`, `losses`, `ties`.
Verdict: `inconclusive` when `pair_groups < 2` or `abs(mean_delta) <= stderr`; else
`winner` with the value name. `reason` is always populated.

- [ ] Test: two pair groups where `spectrum` beats `h3` by 1 and 2 stars ⇒ verdict names
      `spectrum`, `pair_groups == 2`, `mean_delta == 1.5`. One pair group only ⇒
      `inconclusive` with reason mentioning the group count. Marginal cells always carry `n`.

```python
    @classmethod
    def from_ui(cls, ui: dict) -> "Graph"
```
